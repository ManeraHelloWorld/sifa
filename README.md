# Sifa

**0.2 / Android Integration Preview — техническая сборка для Windows 10/11 x64.**

Sifa теперь открывает собственное окно Windows и управляет настоящим Android
через отдельно установленный Android Emulator из Android SDK. Старый
экспериментальный процессор не используется для загрузки Android.

**Совместимость актуальной Standoff 2, вход в матч и игровой FPS пока не
подтверждены. Эту версию нельзя считать готовой заменой игровым эмуляторам.**
Наличие Google Play в образе само по себе не доказывает доступность игры,
работу аккаунта или её совместимость.

## Скачать приложение Windows

[Скачать архив с Sifa.exe — Android Integration Preview](https://github.com/ManeraHelloWorld/sifa/actions/runs/41060984542/artifacts/12978644454)
(для скачивания войдите в GitHub).

1. Скачайте артефакт **Sifa-Android-integration-preview**. Если прямая ссылка
   не открылась, найдите его в разделе **Artifacts** внизу
   [страницы сборки](https://github.com/ManeraHelloWorld/sifa/actions/runs/41060984542).
2. Распакуйте скачанный ZIP, затем находящийся внутри
   `Sifa-Android-integration-preview.zip`.
3. В полученной папке **Sifa** откройте **Sifa.exe**. Компилировать программу
   и устанавливать Visual Studio для этого не нужно.
4. Подготовьте Android по инструкции ниже: в архиве приложения нет SDK
   и образа Android. Для Sifa создайте отдельное новое устройство.

Начальные настройки: **1280×720, 2 ядра, 2048 МБ памяти Android**, GPU — auto;
список доступных CPU/RAM ограничивается параметрами ПК. Это память гостевого
Android, а не требование к общему объёму памяти компьютера: Windows и движку
тоже нужны ресурсы. Производительность на слабых ПК ещё не измерена.

Архив собран из commit `821442b`. Обязательная Windows-задача прошла сборку,
Defender, тесты и проверку окна приложения. У всего запуска CI отображается
ошибка из-за обновления Defender в отдельной дублирующей диагностической
задаче; [подробности проверок](docs/validation.md).

## Что делает эта версия

- Находит установленный Android SDK и созданные Android-устройства (AVD).
- Запускает выбранное устройство в отдельном нативном окне Android Emulator;
  CPU, RAM и режим GPU действительно передаются движку.
- Проверяет загрузку Android, наличие Google Play и установленной Standoff 2.
- Открывает Play Store, страницу игры или установленную игру по запросу пользователя.
- Передаёт экспериментальные игровые касания через постоянное соединение:
  движение WASD, мышь, стрельба и дополнительные действия. Координаты кнопок
  нужно согласовать с раскладкой HUD игры. Проверки и ограничения описаны ниже.
- Останавливает только запущенную ею Android-машину. Не отключает Defender,
  не устанавливает драйверы, не меняет UEFI и не собирает пароль Google.

Основой Android служит **Android Emulator / QEMU**, а не BlueStacks или LDPlayer.
Sifa не выдаёт этот движок за собственную разработку и не включает чужие образы
Android, компоненты Google Play или файлы игры в свой архив.

## Как подготовить Android

Первичная настройка пока требует Android Studio. Автоматического установщика
Android и готового игрового образа в Sifa ещё нет.

1. Установите [Android Studio с официального сайта](https://developer.android.com/studio).
   Пройдите официальный мастер установки SDK и ознакомьтесь с его условиями.
2. Через **SDK Manager → SDK Tools** установите **Android Emulator** и
   **Android SDK Platform-Tools**. Для этой версии используйте актуальный
   Android Emulator 37.x. Запишите **Android SDK Location**.
3. Откройте **Device Manager** (на стартовом экране может называться
   **More Actions → Virtual Device Manager**) → **Create Virtual Device**.
   Выберите телефон с отметкой **Google Play** и официальный образ
   **Google Play x86_64**. В автоматической проверке использован **API 35**.
   Образ **Google APIs** без Play Store для входа в
   магазин не подходит. При создании устройство получает имя AVD.
4. Для аппаратного ускорения на Windows включите виртуализацию процессора
   в UEFI и системный компонент **Windows Hypervisor Platform**, затем
   перезагрузите ПК. Sifa проверяет доступность ускорения перед запуском;
   программная эмуляция CPU не предлагается как игровой режим.
5. Откройте **Sifa.exe**, укажите папку SDK, если она не нашлась автоматически,
   и нажмите **Обновить список**. Выберите созданный AVD и нажмите
   **Запустить Android**. Пример обычного пути SDK:
   `%LOCALAPPDATA%\Android\Sdk`.
6. При первом подключении к существующему AVD Android может показать
   **«Разрешить отладку по USB?»**. Разрешите подключение своей Sifa в самом
   Android. Флажок «Всегда разрешать с этого компьютера» сохраняет доверие
   к компьютеру. Приложение не подтверждает этот запрос автоматически.
   Известное ограничение: ранее использованный AVD может остаться в состоянии
   `unauthorized` без диалога; этот сценарий пока не исправлен. Для первичной
   проверки нужен отдельный новый AVD, созданный для Sifa.
7. Дождитесь статуса **Android работает**. В открывшемся Android можно открыть
   **Google Play** и самостоятельно войти в аккаунт. Кнопка **Игра в Play**
   открывает страницу Standoff 2; установка выполняется самим магазином.
   Кнопка запуска игры становится доступной только после обнаружения пакета.

Sifa не принимает пароль Google: ввод выполняется непосредственно в Android.
Если игра недоступна в магазине, не запускается или запрещает такую среду,
это означает, что совместимость ещё не достигнута; приложение не маскирует
эмулятор и не обходит проверки игры.

## Управление

В окне Sifa доступна кнопка **Управление** после загрузки Android.
Экспериментальный режим использует Windows Raw Input и несколько касаний.
**F8** включает/выключает захват над окном своей Android-машины; **Esc**
освобождает управление. При потере фокуса касания отпускаются.
Положение кнопок, зона движения и чувствительность задаются в настройках
ввода. Множитель чувствительности — расстояние касания на отсчёт мыши;
он не является обещанием конкретных см/360° в игре.

Нельзя оценить качество прицеливания или задержку по лабораторному тесту.
Нужны проверки в настоящем матче на Windows с конкретной мышью и настройками игры.

## Сборка приложения

Windows: установите Visual Studio 2022 Build Tools с **Desktop development
with C++**, Windows SDK и CMake. Из полного исходного архива запустите:

```bat
tools\build-windows.cmd
```

Результат: `build-msvc\Release\Sifa.exe`. Сборщик не запускает полученные EXE.
Перед запуском выполните проверку Defender:

```powershell
powershell -NoProfile -File .\tools\scan-windows.ps1 -Path .\build-msvc\Release -ReportPath .\build-msvc\defender-scan.json
```

Если политика компьютера запрещает PowerShell-скрипты, используйте разрешённую
проверку через Windows Security; не обходите политику ради запуска проекта.
При детекте не отключайте защиту и не восстанавливайте файл из карантина.

GitHub **Code → Download ZIP** содержит исходники. Готовые тестовые сборки
публикуются только после успешной сборки, Defender-проверки и тестов в
[GitHub Actions](https://github.com/ManeraHelloWorld/sifa/actions).
Артефакт новой версии называется **Sifa-Android-integration-preview**;
старый **Sifa-Windows-preview** относится к прежней лаборатории.
Для скачивания артефактов нужен вход в GitHub. Внешний ZIP артефакта содержит
внутренний ZIP приложения: распакуйте оба, затем откройте `Sifa/Sifa.exe`.
Android SDK и AVD скачиваются отдельно через официальные инструменты.

Linux используется для разработки и проверок ядра интеграции:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 4
ctest --test-dir build --output-on-failure
./build/sifa --android list --sdk /path/to/Android/Sdk
```

Windows-приложение не требует установленных Python или Node.js. Они нужны
только для части тестов. Настройки Sifa хранятся в `%LOCALAPPDATA%\Sifa`.
Данные Android и аккаунта сохраняются в выбранном AVD официальным движком.

## Проверки и ограничения

[docs/android-runtime.md](docs/android-runtime.md) описывает запуск процессов,
ввод, внешние зависимости и воспроизводимую проверку настоящего Android.
[docs/validation.md](docs/validation.md) фиксирует отдельно проверенные и
непроверенные возможности. Успешные тесты кода и сканирование не доказывают
совместимость игры, безопасность всех внешних компонентов или превосходство
по FPS.

Лаборатория 0.1 сохранена для разработчиков: `Sifa.exe --lab`, `--demo`,
`--diagnostics`. Её демонстрационные инструкции и браузерный тест мыши не
используются как доказательство работы Android или игровой производительности.

Предыдущая сборка 0.1 была отозвана после детекта
`Trojan:Win32/Sabsik.TE.A!ml`; причина не установлена. История расследования:
[docs/antivirus-investigation.md](docs/antivirus-investigation.md).
JSON-парсер nlohmann/json распространяется с включённой лицензией MIT.
