# Sifa

Самостоятельное экспериментальное ядро виртуальной машины и панель управления для ПК.
Первая версия: **0.1.0 / Engine Preview**. Основная целевая платформа — Windows 10/11 x64;
Linux x64 поддерживается для разработки и проверки ядра.

**Переносимая Windows-сборка доступна в [успешном запуске GitHub Actions](https://github.com/ManeraHelloWorld/sifa/actions/runs/41047108022#artifacts)**
в артефакте **Sifa-Windows-preview**. Она собрана Visual Studio 2022 и прошла
тесты и проверку Microsoft Defender на Windows runner. Это не гарантия безопасности
на всех ПК и не заключение о ложности прежнего обнаружения. Установщика Setup.exe
пока нет; после распаковки запускается `Sifa/Sifa.exe`.

Здесь находятся исходники, интерфейс и инструменты сборки.
Ранее опубликованный Windows EXE отозван после
обнаружения Defender `Trojan:Win32/Sabsik.TE.A!ml`; причина обнаружения не установлена.
Не используйте старый ZIP и не добавляйте его в исключения. Подробнее —
[запись о расследовании](docs/antivirus-investigation.md).

**Standoff 2 и Android пока не запускаются.** Это исполняемый технический прототип,
а не готовая замена Android-эмулятору. В нём нет виртуального GPU, Android-образа,
ARM-транслятора или заявлений о достигнутом игровом FPS. Основа BlueStacks,
LDPlayer, GameLoop и QEMU не используется. Гипервизор операционной системы — WHPX
или KVM — предоставляет аппаратную виртуализацию; код виртуальной машины написан отдельно.

## Что уже работает

- Самостоятельный ограниченный интерпретатор x86-16: MOV, OUT, JMP, NOP, HLT,
  контроль границ программы, лимиты инструкций и вывода.
- Настоящая тестовая гостевая программа: 21 байт, 11 инструкций, вывод `SIFA` и HLT.
- Аппаратные пути через Windows Hypervisor Platform и Linux KVM, с диагностикой
  недоступности. В `auto` программный режим используется, если гипервизор недоступен.
- Встроенная панель на русском языке: профили, ресурсы ПК, тест ВМ,
  измерения времени выполнения, диагностика и лаборатория мыши.
- Сохранение настроек между запусками с ограничениями по ресурсам ПК.
- Расчёт угла по DPI и см/360° без зависимости от разрешения и FPS;
  отдельный планировщик кадров без постоянного активного ожидания.

Профили разрешения, памяти, ядер и целевого FPS сохраняют **планируемые** настройки
будущего Android-гостя. Тестовая ВМ всегда выполняет один и тот же маленький код;
эти профили не изменяют её виртуальное оборудование. Лаборатория мыши работает
в браузере, её события не передаются в игру. Счётчик времени в интерфейсе измеряет
тест ядра, а не FPS Standoff 2.

## Как получить Windows-версию

### Вариант 1: сборка в GitHub Actions

1. Войдите в GitHub и откройте [проверенный запуск сборки](https://github.com/ManeraHelloWorld/sifa/actions/runs/41047108022#artifacts)
   для исходников `9c8a816`.
2. Внизу страницы, в разделе **Artifacts**, нажмите **Sifa-Windows-preview**.
3. Распакуйте скачанный архив GitHub. Внутри лежит ещё один архив
   `Sifa-Windows-preview.zip`, контрольная сумма и отчёт Defender.
4. Распакуйте внутренний ZIP и запустите `Sifa/Sifa.exe`. Откроется локальная
   панель в браузере; не закрывайте консоль, пока работаете с приложением.

Кнопка **Code → Download ZIP** скачивает исходники, а не исполняемую сборку.
Если ваш Defender обнаружит угрозу в новой сборке, оставьте её заблокированной;
проверка CI не отменяет проверку на вашем компьютере.

Для будущих сборок откройте **Actions → Sifa build and tests** и выберите
нужный запуск. Артефакт появляется только при успешных Windows-проверках.

Windows-задача использует Visual Studio 2022, затем проверяет созданные EXE
Microsoft Defender **до** запуска тестов и загрузки артефакта. Если Defender
недоступен, обнаружена угроза или тесты не прошли, артефакт не публикуется.
Зелёная Linux-задача сама по себе не означает готовность Windows-версии.
На одноразовом GitHub-hosted runner CI включает защиту в реальном времени,
убирает исключения сканирования и обновляет определения. Локальные скрипты
эти настройки на пользовательском ПК не меняют.

Если у выбранного запуска артефакта нет, скачать его Windows-сборку нельзя. Журнал задачи
покажет причину. Успешная проверка одного Defender не гарантирует отсутствие
всех угроз и не заменяет проверку антивирусом на вашем ПК.

### Вариант 2: собрать исходники на своём Windows-ПК

1. Скачайте **Code → Download ZIP** из `main` и распакуйте архив. В корне должны
   быть `CMakeLists.txt`, `src`, `include`, `web`, `tests` и `tools`.
2. Установите **Visual Studio 2022 Build Tools** с официального сайта Microsoft.
   Выберите **«Разработка классических приложений на C++»**; нужны MSVC x64,
   Windows SDK и компонент CMake tools for Windows. Это инструменты разработчика,
   они занимают несколько гигабайт.
3. Откройте PowerShell в распакованной папке и выполните:

   ```powershell
   .\tools\build-windows.cmd
   ```

   Скрипт найдёт Visual Studio/CMake и создаст `build-msvc\Release\Sifa.exe`.
   Он **не запускает** приложение или тестовые EXE и ничего не устанавливает автоматически.
4. Обновите определения Defender в «Безопасность Windows», затем проверьте
   созданные EXE, не отключая защиту:

   ```powershell
   powershell -NoProfile -File .\tools\scan-windows.ps1 -Path .\build-msvc\Release -ReportPath .\build-msvc\defender-scan.json
   ```

   Если выполнение `.ps1` запрещено политикой компьютера, не обходите её ради
   запуска проекта. Используйте разрешённую проверку Defender в интерфейсе
   Windows или сборку CI; автоматическое подтверждение сканирования останется недоступным.
   При обнаружении угрозы, ошибке или недоступности проверки остановитесь.
5. Только после успешной проверки и при отсутствии блокировки антивируса:

   ```powershell
   .\build-msvc\Release\Sifa.exe
   ```

   Панель откроется в браузере. Консоль должна оставаться открытой;
   `Ctrl+C` останавливает приложение. Node.js и Python для приложения не нужны.

Самостоятельная сборка не доказывает безопасность и не устраняет автоматически
причину прошлого детекта. Windows-скрипты добавлены для воспроизводимости;
их статус проверки нужно смотреть в CI. Прототип всё ещё не запускает Android/игру.

## Работа с приложением

Настройки хранятся в `%LOCALAPPDATA%\Sifa\settings.json` на Windows и
`$XDG_CONFIG_HOME/sifa/settings.json` либо `~/.config/sifa/settings.json` на Linux.
Путь можно переопределить через `--data-dir`.

```sh
sifa --help
sifa --diagnostics
sifa --demo software
sifa --demo hardware
sifa --no-open --data-dir ./local-data
```

Панель слушает только `127.0.0.1` на случайном свободном порту. Первая ссылка из
консоли открывает локальную сессию, затем ключ убирается из адресной строки.
Это локальное приложение, а не сервис для публикации в Интернете.

## Сборка из исходников

Требуются компилятор C++20 и CMake 3.21+. Зависимости ядра — стандартная библиотека
и API ОС. JSON-парсер nlohmann/json 3.12.0 включён в исходники с лицензией MIT.

Windows: проще использовать `tools/build-windows.cmd` выше. Эквивалентные ручные
команды для Developer PowerShell (после сборки нужно выполнить Defender-проверку
из предыдущего раздела, и только затем запускать тесты или приложение):

```powershell
cmake -S . -B build-msvc -G "Visual Studio 17 2022" -A x64
cmake --build build-msvc --config Release --parallel 2
# Сначала Defender-проверка build-msvc\Release, затем:
ctest --test-dir build-msvc -C Release --output-on-failure
```

Linux: GCC 12+ или Clang с поддержкой C++20, CMake, make/ninja:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 4
ctest --test-dir build --output-on-failure
./build/sifa
```

Python 3 нужен только для дополнительных HTTP-интеграционных тестов. При его
наличии CMake добавляет их автоматически. Без Python доступны три C++ набора.
Для UI-проверки: установите Playwright вне исходников и запустите
`tests/ui_smoke.cjs` с `SIFA_EXECUTABLE` и `PLAYWRIGHT_MODULE` — параметры описаны в файле.

Аппаратный режим на Windows требует включённой виртуализации в UEFI и компонента
**Windows Hypervisor Platform**. На Linux нужен доступ текущего пользователя к
`/dev/kvm`. Программа не меняет компоненты ОС, UEFI или права доступа автоматически.

## Реалистичный путь к Standoff 2

Архитектура и этапы описаны в [docs/architecture.md](docs/architecture.md).
Следующие необходимые компоненты: загрузка Linux/AOSP, прерывания и таймеры,
дисковые и сетевые устройства, графический конвейер, звук и нативный ввод.
Поддержка ARM-only библиотек игры потребует отдельного решения; разрешённость
и техническую совместимость эмулятора с актуальной версией игры нужно проверять отдельно.

«Максимальный FPS на любом слабом ПК» не является проверяемой гарантией.
Цель дальнейших измерений — стабильное время кадра, p95/p99 задержки ввода,
потребление памяти и качество изображения на зафиксированных конфигурациях ПК.
До запуска реального гостя и игры сравнения с другими эмуляторами не выполняются.

## Проверки и сторонний код

`tests/` проверяет поведение интерпретатора, ошибки и бесконечные циклы,
нормализацию профилей, DPI/см360, планирование кадров, HTTP-сессию,
реальное выполнение гостя и сохранение настроек после перезапуска.
Сборки Linux/Windows и тесты настроены в `.github/workflows/build.yml`.

Только JSON-парсер заимствован как инфраструктурная библиотека:
[`include/third_party/JSON_LICENSE.MIT`](include/third_party/JSON_LICENSE.MIT).
Игровые файлы и образы Android в репозиторий не включены.
