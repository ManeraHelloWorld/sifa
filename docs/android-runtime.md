# Android-интеграция Sifa 0.2

Это техническая интеграция отдельно установленного Android Emulator. Она не
доказывает, что Standoff 2 доступна, запускается или работает быстрее других
эмуляторов. Следующий критерий продукта — установленная актуальная игра и
реальный матч на Windows с аппаратным ускорением.

## Исполнение

```text
Окно Sifa (Win32) → контроллер процессов → Android Emulator → AVD / Android
                         ↓
               отдельный localhost ADB → статус / Play Store / запуск приложения
Windows Raw Input → mapper касаний → постоянная аутентифицированная консоль
```

`android_runtime.cpp` ищет SDK через выбранную папку, `ANDROID_HOME`,
`ANDROID_SDK_ROOT` и стандартный путь пользователя. AVD читаются из штатного
реестра Android; конфигурация существующего AVD не переписывается. Проверяются
имя, ABI, версии настоящих tools и доступность ускорения. Старт получает
реальные `-memory`, `-cores`, `-gpu`, `-skin` и `-accel on`.

На Windows используются Unicode `CreateProcessW`, явный executable и список
разрешённых наследуемых handles. Процесс до запуска помещается в отдельный
Windows Job; остановка и закрытие касаются только этого Job. На Linux
используется отдельная process group. Вывод ограничен, журналы сохраняются
в каталоге Sifa. Нет запуска через shell или конкатенации пользовательских
путей в командную строку shell.

Каждый запуск использует собственный foreground ADB на свободном localhost
порту. Перед запуском официальный `adb keygen` создаёт ключ в новом каталоге
экземпляра. Этот же ключ передаётся ADB через `ADB_VENDOR_KEYS` и движку через
его каталог конфигурации: новые версии ADB и Emulator по-разному трактуют
Android home variables, без согласования ключа гость остаётся offline. Команды указывают точный serial, проверяют принадлежность сокета
своему дереву процессов и соответствие имени AVD. Нет `kill-server`, `killall`,
`wipe-data` или команд произвольному подключённому телефону. Официальный ADB
может создавать стандартные ключи в пользовательской `.android`.

Статус Android читается через `getprop sys.boot_completed`; пакеты Play Store
и Standoff 2 определяются через package manager гостя. Наличие пакета означает
установку, а не успешную работу приложения. Открытие магазина/игры выполняется
по нажатию соответствующей кнопки. Аккаунт вводится только в самом Android.

## Экспериментальное управление

`game_mapping.cpp` преобразует WASD, движение мыши и действия в несколько
контактов. Диагональ нормализуется. Для мыши используется относительное
смещение, а не число кадров. При достижении границы области прицеливания
контакт отпускается и переставляется с сохранением порядка событий.

`game_input.cpp` отправляет Linux input Protocol B по постоянному TCP-соединению
с аутентифицированной консолью своего emulator. Нет отдельного ADB/shell
процесса на каждое движение. Проверяются диапазоны, ответы консоли, порядок
кадров, размер данных и тайм-аут. Потеря канала приводит к попытке отпустить
все контакты после повторной проверки принадлежности процесса.

`game_input_windows.cpp` использует Raw Input и временное окно захвата над
окном своего Android. Оно принимает обычные клики/клавиши, чтобы они не
дублировали игровые касания движка. F8 переключает режим, Esc и потеря фокуса
освобождают его. Глобальных low-level hooks и журнала клавиш нет. Окно захвата
имеет alpha=1 из 255, что может слегка влиять на яркость изображения.

Профиль включается явно и требует настройки координат HUD, геометрии и
поворота экрана. Транспорт подтверждает приём команды консолью; это не
автоматическое доказательство распознавания касания игрой. Чувствительность
является коэффициентом raw counts → перемещение касания. Без проверки
внутриигровой чувствительности нельзя обещать определённые см/360°.

## Проверка настоящего Android

Для разработчика с уже установленным SDK и созданным AVD:

```sh
sifa --android list --sdk /path/to/Android/Sdk
sifa --android smoke My_AVD --sdk /path/to/Android/Sdk --headless --boot-timeout 300
```

Проверка запускает выбранный AVD, ожидает настоящий `sys.boot_completed`,
проверяет пакеты и останавливает только свою машину. Не запускайте её на AVD,
который уже открыт в другом экземпляре. Данные AVD сохраняются штатным движком.
`--software-cpu` разрешён только как явный эксперимент без гипервизора; он
не включается автоматически и не подходит для оценки игры. Как и обычный
запуск, тест обращается к существующему AVD и создаёт его рабочие данные.

Windows UI дополнительно проверяется `tests/desktop_smoke.ps1` после Defender.
Он запускает настоящий EXE с изолированными настройками без SDK, проверяет
окно, недоступность неподготовленного запуска, отзывчивость и закрытие. Этот
тест не подменяет проверку Android или игры на Windows.

## Распространение и следующие проверки

Sifa распространяет только свои исходники/EXE и разрешённую библиотеку JSON.
Android Emulator, SDK, образы Google Play и игра устанавливаются отдельно
официальными средствами по их условиям. Sifa не принимает эти условия за
пользователя, не копирует GMS из других эмуляторов и не заявляет сертификацию.

До готового игрового продукта остаются проверка совместимости текущей игры,
готовый и проверенный HUD-профиль, удобная первичная настройка, проверка звука,
сравнение GPU/frametime/1% low и input-to-photon на реальных Windows ПК.
Высокий FPS, красивая картинка, низкая задержка и безопасность не следуют
автоматически из выбора готового ядра или успешной компиляции.
