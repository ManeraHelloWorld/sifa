# Проверка Sifa 0.2

Статус 30 октября 2026 года. Пункты ниже относятся к новой Android-интеграции.
Историческая проверка 0.1 приведена отдельно в конце файла.

## Опубликованная сборка

Исходники приложения: commit `821442bfefb0d1bcd02187cc1bfe5d04126d35da`.
[Архив Sifa-Android-integration-preview](https://github.com/ManeraHelloWorld/sifa/actions/runs/41060984542/artifacts/12978644454)
создан в [CI 41060984542](https://github.com/ManeraHelloWorld/sifa/actions/runs/41060984542).

- **Обязательная Windows-задача прошла**: сборка MSVC, обновление и проверка
  состояния Defender, рекурсивное сканирование всех Release EXE, CTest,
  настоящий нативный интерфейс и упаковка совпадающих с отчётом байтов.
  [Результат Windows](https://github.com/ManeraHelloWorld/sifa/actions/runs/41060984542/job/124081491449).
  В том же запуске опубликованы отчёты CTest и снимок окна приложения.
- Linux-тесты и обе загрузки настоящего Google Play API35 x86_64 Android
  на KVM прошли. После первой загрузки и перезапуска Sifa вернула
  `boot_completed=true`, `play_store_installed=true`, `stopped=true`.
  В обоих случаях `game_installed=false`: игра в эту проверку не входит.
- Дополнительная дублирующая задача **Windows application UI evidence only**
  завершилась ошибкой на шаге обновления определений Defender. Поэтому весь
  workflow помечен как неуспешный. Обязательная задача на другом Windows runner
  выполнила собственные сканирование и проверку интерфейса успешно; дополнительная
  задача не использовалась для обхода условий публикации.

Успешный скан этой сборки не объясняет прежние детекты и не гарантирует
результат на другом ПК. Android с WHPX, вход в Google Play и Standoff 2
на Windows по-прежнему требуют проверки.

## Выполненные проверки и известные ограничения

- Release Linux: сборка проходит. Все **7 наборов CTest** проходят: VM, настройки,
  тайминги, Android runtime, mapper, транспорт ввода, HTTP API лаборатории.
- Android runtime: **39 проверок** с настоящими подпроцессами и локальными
  сокетами, но фиктивным SDK. Это проверяет управление процессами и аргументами,
  а не загрузку Android. Проверяются отдельный ADB, целевой AVD, выход процессов,
  неизменность конфигурации устройства, неправильные пути/параметры,
  сохранение одного ключа при повторных запусках и генерация только при его
  отсутствии.
- Ввод: тестируются одновременные контакты, диагонали, чувствительность,
  снятие нажатий и настоящий TCP-клиент против тестовой консоли, включая
  аутентификацию, фрагментацию ответов, ошибки и закрытие соединения.
- MinGW Windows x64: приложение и новые тесты компилируются. Это не запуск
  Windows UI, не проверка WHPX и не измерение физического ввода.
- Нативная проверка `tests/desktop_smoke.ps1` **прошла** в [Windows CI](https://github.com/ManeraHelloWorld/sifa/actions/runs/41056232920/job/124064345733)
  на commit `8df9391`: настоящее окно, отзывчивость, отсутствие SDK, сохранение
  минимального профиля 1280×720, закрытие и перенаправленный CLI. Перед запуском
  настоящий Sifa.exe прошёл Defender. Это отдельная проверка приложения;
  полный выпускной процесс того же запуска остановился на ошибке обновления
  определений Defender. Она не отменяет предыдущий детект тестового EXE.
- Официальный Android Emulator 37.2.13 и Google Play Android 11/API30 revision10
  проверяются отдельно в облаке. Архивы сверены с контрольными суммами
  официального каталога Google. `/dev/kvm` и аппаратного GPU здесь нет.
  Обычный запуск Sifa правильно отклоняет отсутствие ускорения. В ручном
  программном запуске подтверждены `sys.boot_completed=1`, пакет Google Play
  (`Phonesky.apk`) и разрешение launcher-intent магазина. Изображение Android
  настоящее, но под TCG возникают ANR System UI; это не подтверждает стабильность
  на Windows, игровой запуск или аппаратную производительность.
- Первое нативное CI новой версии: [41053655568](https://github.com/ManeraHelloWorld/sifa/actions/runs/41053655568),
  commit `156d92f`: Windows-компиляция прошла; Defender заблокировал чтение
  `android_runtime_tests.exe` как вируса/потенциально нежелательного ПО.
  Тесты Windows и публикация EXE остановлены. Название детекта из этого вывода
  неизвестно. Повторный запуск [41054370993](https://github.com/ManeraHelloWorld/sifa/actions/runs/41054370993)
  (`fecd465`) установил название: **Trojan:Win32/Malex.gen!F**, тот же
  `android_runtime_tests.exe`; Defender сообщает успешное действие над угрозой.
  Причина и ложность срабатывания не установлены. Следующие
  изменения авторизации ADB исправляют подтверждённую ошибку подключения,
  а не обходят Defender. Защита и условия выпуска не ослаблены.
- Запуск существующего ручного AVD через новый Sifa Runtime **не прошёл**:
  после сохранения собственного ключа SDK загрузил Android (246 812 мс в TCG),
  но ADB сообщил `unauthorized`; диалог разрешения не появился. Проверки
  `sys.boot_completed` и пакетов через этот Runtime завершились неуспешно.
  Два ограниченных запуска корректно остановили свои процессы и закрыли порты.
  Это отдельный результат от успешной ручной проверки исходного SDK-профиля.
  Это известная проблема повторного использования AVD с прежним SDK-ключом;
  данные устройства не сбрасывались ради прохождения проверки.
- **Настоящий Sifa Runtime с чистым Google Play API35 x86_64 AVD прошёл два
  запуска на KVM** в [CI 41059034199](https://github.com/ManeraHelloWorld/sifa/actions/runs/41059034199),
  commit `c2f47bf`: обе записи возвращают `ok=true`, `boot_completed=true`,
  `play_store_installed=true`, `stopped=true`, `game_installed=false`.
  Проверены первая загрузка, остановка и повторная загрузка с постоянным ключом.
  Это обязательный выпускной тест. Он не включает вход в Google-аккаунт,
  установку Standoff 2 или игру; GPU в этом тесте программный, CPU использует KVM.
- Реальный Android input device проверен через `dumpsys input`: ABS X/Y
  0–32767, tracking ID 0–65535, rotation 0. События из `ConsoleInput`
  распознаны Android: [снимок `P: 0 / 6`](evidence/android-six-touch-tcg.png)
  показывает максимум шесть контактов и ноль оставшихся нажатий. На снимке
  также виден ANR: он не скрыт и не считается успешной проверкой игрового
  интерфейса. Полный getevent-журнал нажатий получить не удалось; записаны
  отпускания. После обнаружения диапазона ID добавлен тест 70 000 циклов.
- Тестовые SDK-инструменты теперь собираются как два отдельных, явно
  обозначенных fixture-executable. Тест больше не копирует собственный EXE.
  Все 39 поведенческих проверок сохранены; helpers размещаются внутри Release
  и проходят тот же рекурсивный Defender-контроль до выполнения тестов.
  Такое разделение улучшает структуру теста; оно не доказывает причину или
  ложность предыдущего обнаружения.
- Шесть проверок правил упаковки проходят. Новый EXE публикуется только после
  настоящего успешного Defender-сканирования; фиктивные отчёты тестов для этого
  не применяются.

**Не проверено:** вход в Google Play, доступность актуальной Standoff 2, запуск
матча, звук игры, корректность её HUD-профиля, Windows Raw Input на физической
мыши, реальный GPU-путь, FPS/1% low/время кадра/задержка. Программный Android
в облаке не подходит для выводов о Windows-производительности.

## Историческая проверка Sifa 0.1.0

Проверка выполнена 30 октября 2026 года в облачной Linux x86_64 среде.
Результаты относятся к текущему прототипу, а не к совместимости с Android-играми.

## Подтверждено

- Release-сборка Linux: GCC 14.2, CMake 3.31.6, C++20.
- `ctest`: четыре набора прошли — VM, настройки, тайминги и HTTP API.
- VM: 30 проверок программного ядра, включая границы инструкций, недопустимые
  переходы, бесконечные циклы, лимит вывода и исполнение реального байткода.
- Настройки: ограничения CPU/RAM, профили, дробная чувствительность,
  зависимость от DPI и независимость математики ввода от FPS/разрешения.
- Тайминги: статистика распределений и детерминированные дедлайны без
  накопления пропущенных кадров.
- HTTP: десять интеграционных тестов против запущенного executable. Проверены
  гостевой вывод, измерение 200 запусков, диагностика, авторизация, запрещённый
  Origin/Host, ошибки JSON, сохранение файла и загрузка настроек после рестарта.
- Chromium + Playwright: проверены четыре раздела, запуск тестового гостя,
  сохранение калибровки, профили, измерение 200 запусков, скачивание диагностики,
  настоящие Pointer Lock и события мыши, а также отсутствие горизонтального
  переполнения на ширине 390 px. Физический DPI и аппаратная задержка мыши
  этой автоматизацией не проверяются. Внешних сетевых запросов и ошибок JS нет.
- Windows x64: кросс-компиляция Release с MinGW-w64 GCC 14, включая настоящий
  код Windows Hypervisor Platform и три C++ test executable.
- Windows executable содержит интерфейс; импортирует только системные DLL:
  `bcrypt.dll`, `KERNEL32.dll`, `msvcrt.dll`, `SHELL32.dll`, `WS2_32.dll`.
  Этот перечень относится к первоначальной MinGW-сборке, которая впоследствии отозвана.
- Новая нативная Windows-сборка Visual Studio 2022: [GitHub Actions, запуск 41047108022](https://github.com/ManeraHelloWorld/sifa/actions/runs/41047108022),
  исходники `9c8a816`. Windows-задача завершилась успешно: сборка, включение
  защиты и обновление Defender на временном runner, сканирование, CTest и
  упаковка точных проверенных байтов. Опубликован артефакт `Sifa-Windows-preview`
  с отчётом сканирования. Linux-задача также прошла.
- Шесть тестов правил упаковки: отсутствие отчёта, изменённый файл, устаревший
  отчёт или отозванный SHA-256 блокируют создание пакета. Тестовые отчёты —
  искусственные фикстуры; они не используются для публикации приложения.

## Не проверено и не реализовано

- Аппаратное выполнение Linux KVM **пропущено**: в среде отсутствует `/dev/kvm`.
- Нативный Windows executable запускался в автоматических CLI/HTTP-тестах CI.
  Это не подтверждает работу аппаратного WHPX, драйверов или интерактивного
  интерфейса на конкретном пользовательском ПК.
- Успешный скан новой сборки не доказывает ложность детекта
  `Trojan:Win32/Sabsik.TE.A!ml` первоначальной сборки и не гарантирует отсутствие
  обнаружений на другом ПК. Причина исходного детекта остаётся неустановленной.
- Android, виртуальный GPU, ARM-трансляция, звук, игровой клавиатурно-мышиный
  ввод и запуск Standoff 2 **не реализованы**.
- Игровой FPS, время кадра игры, нагрузка GPU и задержка input-to-photon
  **не измерялись**. Из времени маленького гостя нельзя получить эти показатели.

## Воспроизведение

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 4
ctest --test-dir build --output-on-failure
./build/sifa --diagnostics
./build/sifa --demo software
```

HTTP- и браузерные тесты требуют разрешённых loopback-сокетов. Если песочница
запрещает их создание, это ограничение окружения; не следует считать нулевой
запуск тестов успешной проверкой сервера.

Браузерная проверка запускается отдельно через `tests/ui_smoke.cjs` с установленными
Playwright и Chromium; они нужны только разработчику, не пользователю Sifa.

```sh
PLAYWRIGHT_MODULE=/path/to/playwright CHROMIUM_EXECUTABLE_PATH=/path/to/chromium node tests/ui_smoke.cjs
```
